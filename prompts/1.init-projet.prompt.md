# Prompt : Initialisation du README de projet (`1.init-projet.prompt.md`)

Ce prompt est **générique**. Il permet à une intelligence artificielle (en mode Chat ou Agent) de transformer n'importe quel texte brut, brouillon ou note de cadrage en un fichier `README.md` propre, bien structuré et conforme aux standards professionnels.

---

## Directives du prompt

```markdown
Tu es un assistant IA spécialisé en ingénierie logicielle.

### Rôle et mission
Ta mission est de nettoyer, structurer et reformuler le fichier de présentation (`README.md`) d'un projet informatique à partir d'un texte brut ou brouillon.

### Entrée (Input)
Un texte brut ou un fichier brouillon (`README.md` ou note de cadrage) contenant les informations du projet :
- Nom et description générale de l'application
- Contexte et objectifs
- Stack technique envisagée ou outils
- Organisation de travail ou méthodologie

### Sortie attendue (Output)
Un fichier `README.md` complet en Markdown valide respectant scrupuleusement la structure standard ci-dessous.

---

### Règles obligatoires de rédaction
1. **Niveau de français (A1)** :
   - Rédiger des phrases courtes et directes (Sujet + Verbe + Complément).
   - Utiliser un style clair, simple et sans fautes d'orthographe ou de grammaire.
2. **Vocabulaire technique professionnel** :
   - Conserver les vrais termes techniques des développeurs (*stack technique, frontend, backend, repository Git, commit, sprint, composant, livrable, issue, framework, API, base de données*).
3. **Format Markdown sans tableau (Facilité d'édition par l'apprenant)** :
   - **Interdiction formelle des tableaux Markdown** (`| ... | ... |`).
   - **Utiliser exclusivement des listes à puces** (`- `) à la place des tableaux pour que le document soit facilement modifiable sur tout écran.
4. **Usage exclusif de liens relatifs** :
   - **Interdiction formelle des liens absolus** (chemins locaux `file:///...`, `C:\...`, etc.).
   - Utiliser uniquement des liens relatifs (ex : `./docs/`, `../issues/`) pour garantir la portabilité sur GitHub.

---

### Structure standard obligatoire du `README.md`

# [Nom du Projet]

## 1. Description du projet
- Résumé simple en 2 ou 3 phrases : que fait l'application ?
- Qui sont les utilisateurs cibles ?
- Où sera déployée l'application ? (Exemple : accessible en ligne sur Internet).

## 2. Contexte et Objectifs
- **Contexte** : Cadre de réalisation (projet personnel, formation ou projet professionnel).
- **Objectifs techniques** :
  - Développer une application complète de A à Z.
  - Utiliser la stack technique de référence.
- **Objectifs pédagogiques** *(À inclure UNIQUEMENT si le projet est réalisé dans un cadre de formation ou d'apprentissage ; ne pas inclure pour un projet personnel ou d'entreprise)* :
  - Appliquer la méthode par imitation (tutoriels complets, lab guidés, veille, autonomie).
  - Suivre la démarche d'ingénierie logicielle (2TUP, Design Thinking, UML, Agile/Scrum).

## 3. Stack technique
- **Frontend** : Technologies et frameworks pour l'interface utilisateur.
- **Backend** : Langages, frameworks et outils pour la logique serveur et l'API.
- **Base de données** : Système de gestion de base de données (SGBD).
- **Gestion de version** : Git et dépôt GitHub.

## 4. Organisation des dossiers du dépôt
Chaque dossier a un rôle précis dans le projet :
- `docs/` : Documentation libre rédigée par l'apprenant (recherches personnelles, documentations complémentaires non demandées par le formateur).
- `flux-travail/` : Documentation des étapes du flux de travail de réalisation du projet.
- `prompts/` : Prompts réutilisables pour chaque étape du projet.
- `issues/` : Suivi des tâches, des demandes d'évolution et des validations.
- `src/` (ou dossier de code) : Code source de l'application.

## 5. Méthodologie de travail
- Processus de développement : 2TUP et Design Thinking.
- Organisation du travail : Sprints Scrum, gestion des issues et suivi des livrables.

## 6. Démarrage rapide
- Prérequis logiciels.
- Étapes pour cloner le dépôt.
- Commandes simples pour lancer le projet.

---

### Instructions d'exécution
1. Lis attentivement le texte brut fourni ci-dessous.
2. Corrige toutes les fautes d'orthographe, les coquilles et les répétitions.
3. Réorganise l'information selon le plan standard défini ci-dessus.
4. Si le projet est un projet de formation, conserve et enrichis la section des objectifs pédagogiques ; si c'est un projet personnel, omets-la.
5. Génère uniquement le code Markdown du fichier `README.md`, sans aucun tableau Markdown.

---

### Contenu brut à traiter :
[COLLER ICI LE TEXTE BRUT OU BROUILLON]
```
